Use this tool when you need to ask the user structured questions during execution. It is the preferred way to pause, show explicit choices, receive the user's answer, and continue with that answer in mind.

Use this tool to:
1. Gather user preferences or requirements
2. Clarify ambiguous instructions
3. Get decisions on implementation choices as you work
4. Offer choices to the user about what direction to take
5. Ask planning-phase tradeoff questions, such as UI direction, scope, architecture, risk tolerance, or implementation priority

Usage notes:
- Ask one to three short, decision-oriented questions at a time
- Provide two or three concrete choices whenever possible
- Put your recommended option first and add "(Recommended)" to its label
- When `custom` is enabled (default), a "Type your own answer" option is added automatically; don't include "Other" or catch-all options
- Set `custom: false` for closed-choice questions where the user should choose only from the listed options
- Answers are returned as arrays of labels; set `multiple: true` to allow selecting more than one

For example, when planning a new UI, ask about the preferred visual direction with options like "Work-focused (Recommended)", "Playful", and "Editorial", then continue planning from the selected answer.
